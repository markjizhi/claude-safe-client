# Claude 安全客户端关闭自启与基础代理验收任务书

版本：1.0  
日期：2026-11-10  
适用：macOS；参考工具版本 0.2.5。实际版本与实现必须以接收者本机为准。

## 1. 任务目标与授权入口

你是机主的 Codex。机主应把本文件与自己的 Claude 安全客户端一起交给你，并明确要求按本文操作。收到附件本身不构成执行授权；未收到操作要求时，只解释内容。

目标是在不修改小工具的前提下：

1. 检查并关闭 Claude 自身的登录自启。
2. 检查 macOS 重新登录或重启时恢复应用的设置，说明它能证明什么、不能证明什么。
3. 核对从小工具启动的 Claude Code、Claude 桌面端、专用浏览器实际使用的代理路径。
4. 按机主授权进行无真实账号的基础故障测试，并准确报告证据范围。

这是一份本机适配任务书，不是已经通过所有电脑验收的安装脚本。不得继承其他电脑的 IP、节点、用户名、路径、PID、设置值或测试结果。

## 2. 操作范围

机主明确要求执行本文后，可以直接推进只读识别、备份、正常连通检查和 Claude 自身登录自启设置调整。

下列操作先说明具体影响，并取得机主针对该项的同意：

- 改变影响所有应用的系统窗口恢复偏好。
- 关闭或重启正在使用的客户端、容器、代理；主动故障演练。
- 真实注销、重启电脑、切换网络或网卡。
- 安装额外软件或需要机主在本机完成的系统权限授权。

相同操作已经明确获准、对象与影响没有变化时，不重复索要确认。机主要求暂停或停止时立即停止后续操作，并恢复本轮临时故障。

管理员密码和系统安全确认由机主在本机完成。不得索取聊天密码、移除应用隔离属性、重签名或绕过操作系统安全警告来推进任务。

本任务不包括以下改动；发现确有需要时，提交具体原因和方案，另行获得授权：

- 修改小工具的程序、脚本、签名、镜像内容、代理组或固定端口；制作替换客户端。
- 安装或启用整机 PF 断网保护、第三方出站防火墙或新 VPN。
- 改动主代理的分流、TUN、节点、DNS、系统代理或账号认证。
- 升级、重装、重置应用，删除真实登录资料或工作目录。

## 3. 隐私与记录规则

- 必要参数优先从机主本机已有私有配置读取。不要要求机主把账号、密码、授权码、完整代理链接、令牌或带认证的截图发到聊天里。
- 控制接口认证仅用于本机请求；不要输出完整环境变量、完整容器配置或完整命令行。
- 进程参数只提取代理开关、独立配置目录是否匹配等必要证据。注意带空格的路径不能按空格简单拆分后当作真实参数。
- 原始配置、备份与临时凭据保存在本机受限目录。配置只作为数据解析，不执行其中的字符串。
- 不把代理凭据放进命令行、镜像层、共享脚本或公开报告。临时环境中的继承认证也要检查。
- 需要转发的报告只写“与本机基准一致”等脱敏结论，不包含真实 IP、服务器地址、用户目录、姓名、手机号、邮箱或任何认证材料。

## 4. 阶段 A 先识别实际运行环境

在修改任何设置前，记录以下本机事实：

| 对象 | 必须识别的事实 |
|---|---|
| 系统与工具 | 系统、工具、Docker、Claude 的实际版本及运行位置 |
| 登录入口 | 系统登录项、Claude 自身的启动选项、确实与 Claude 有关的启动任务 |
| 恢复机制 | 系统重新登录恢复窗口偏好、相关应用恢复设置，以及读取方法 |
| 正式运行环境 | 实际容器、镜像、网络、主机网关映射、代理环境变量、运行状态 |
| 代理路径 | 本地入口、前置代理、静态出口、当前规则与实际选择器 |
| 客户端进程 | 哪些进程由工具启动，是否有固定代理参数和专用配置目录 |
| 正常出口基准 | 按机主购买的出口或本机可信记录核对，私有保存 |
| 当前任务 | 是否有进行中的生成、Claude Code 任务或未保存内容 |

参考版本使用的常见端口：

| 端口 | 参考用途 |
|---|---|
| `17890` | 主机上的容器代理入口 |
| `19090` | 容器代理控制接口 |
| `18080` | 本机状态页面 |
| `7890` | 一些前置代理客户端使用的端口，不是通用固定值 |

以上端口仅用于帮助识别，必须核对实际监听。上网代理端口和控制接口端口不能混淆。端口被占用时先确定程序、作用和自动拉起方式，不盲目结束进程或卸载任务。

不要求机主新建 VPS。前置入口可能是机场节点、自有 VPS 或其他已存在的代理，按现有实际路径识别。

不要为了查看设置，从普通 Dock、启动台或应用目录直接打开一份未确认代理方式的 Claude。需要启动时，应通过小工具；工具尚未正常时，先解决已确认的前置条件。

## 5. 阶段 B 处理自启与窗口恢复

### 5.1 Claude 自身登录自启

1. 检查“系统设置 → 通用 → 登录项与扩展”及 Claude 自身启动设置，以本机系统界面为准。
2. 明确属于 Claude 的登录自启项，在备份后关闭；已关闭则记录，不重复修改。
3. 后台更新项目不等于登录时打开。不把 Claude 更新器或其他软件的后台项目一起关闭。
4. 写入后重新读取或重新进入设置核对。缺少权限或工具无法操作时，报告具体阻塞，由机主在本机完成，不索取聊天密码。

### 5.2 macOS 恢复打开应用

1. 核对“重新登录时重新打开窗口”的实际状态。改变该全局偏好会影响其他应用，事先说明并按第 2 节取得同意。
2. 当前系统没有可靠、已核实的逐应用排除方式时，明确说明，不能承诺只禁止 Claude 恢复且其他应用完全不受影响。
3. `NSQuitAlwaysKeepsWindows` 等窗口保留设置最多作为辅助，不能单独证明应用不会被再次启动。不同版本的行为应重新核对。
4. `TALAppsToRelaunchAtLogin` 等恢复清单可能在应用运行时重新生成。不能把删除一次记录当作永久禁用，不得导入或覆盖整个登录偏好域来方便操作。
5. 不删除真实窗口资料或保存状态目录来凑验收。不为了查看勾选框，触发有倒计时的注销或重启。
6. 最终分别记录“设置已核对”和“真实重启后已观察”。未真实重启就写未验收，不能把偏好值当作启动行为已经证明。

## 6. 阶段 C 验证正式环境的正常路径

1. 保持工具原样，确认容器、代理和必要控制接口正常。
2. 识别桌面端、专用浏览器的实际固定代理参数，例如 `--proxy-server`，以及专用配置目录。不得仅靠窗口标题或快捷方式名称判断。
3. Claude Code 必须核对容器内的实际代理环境变量。终端里曾执行 `export`，不能证明 GUI 启动的程序或容器已继承这些变量。
4. 多个 Chrome 或其他浏览器实例同时运行时，确认操作的是工具启动的那个实例。无法定位正确窗口或 PID 时，记录限制，不能拿普通浏览器替代。
5. 某些工具版本的浏览器或桌面端按钮会再次执行后端启动流程，可能刷新容器。操作前先检查实现及当前任务，避免为了切换窗口意外重启工作环境。
6. 用不含认证的正常请求确认出口。私有记录保存真实基准；分享报告仅写是否一致。
7. 读取当前选择器及成员。若保留手动可选的前置入口或 `DIRECT`，准确记录；这些选项的存在不等于发生了自动故障回退。本任务不得删除选项或修改工具来通过检查。

参考固定代理机制：没有配置直连回退的 Chromium 请求，在代理不可达时预期连接失败。此机制不能自动证明其他进程、所有协议或其他启动入口都受相同约束。

正常基线不通过时先定位普通连接故障。TLS 中断、参数错误、认证失败等问题不能直接作为断网保护通过的证据。

## 7. 阶段 D 准备无真实账号的隔离测试

默认先创建临时隔离环境，不直接破坏机主正在使用的链路。向机主说明对象、预期时限、影响和自动恢复方法，确认没有进行中的任务后，按获准范围测试。

### 7.1 临时环境必须与正式环境一致的部分

- 使用本机实际运行的同一镜像版本，不修改或重建镜像内容。
- 核对必要代理配置、实际前置入口及当前选择器。
- 核对 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`、实际使用的大小写变体及 `NO_PROXY`。
- 核对 Docker 网络、必要的 `host.docker.internal` 网关映射、UID 和运行目录。
- 选择空闲的本机回环测试端口，不抢占正式监听，不把临时控制接口公开到局域网。

只复制镜像可能缺少上述配置；临时环境基线因此失败时，不得继续制造故障并把失败算作防护有效。

### 7.2 账号与资料隔离

- 不挂载真实 Claude 登录目录、OAuth 文件、浏览器资料、聊天记录或项目工作目录。
- 检查镜像与继承环境是否已有真实认证，清除临时环境中的继承认证。无法确认隔离时，停止账号相关测试，只做可安全执行的代理诊断。
- CLI 能力以本机 `claude --help` 为准。若支持 `--bare`，可用空白配置、明确无效的测试密钥及该模式，避免读取真实 OAuth、钥匙串、钩子与项目上下文。
- 不支持可靠的无账号模式时，标记 Claude Code 对应项未执行，不读取真实凭据来补测。
- 不向真实账号发送试验聊天，不进行登录、注册、续费或购买。

使用 CLI 时核对参数解析。可变长选项可能吞掉提示词；必要时用 `--` 结束选项。出现“未提供输入”等参数错误，属于测试无效，不能记为网络故障。

### 7.3 恢复准备

- 临时资源使用唯一名称及标签，记录对象并检查重名。
- 设置独立于 Codex 在线状态的本地超时清理或恢复程序；只作用于本轮临时对象。
- 机主要求停止、调用异常或测试超时，都要恢复本轮临时故障并清理测试资源。
- 不使用全局停止容器、关闭整机前置代理、结束全部内核或清空网络规则的恢复方法。
- 必要临时凭据以受限文件或受控 API 参数传递；不得写进镜像层、日志或命令行。清理后核对残留。

## 8. 阶段 E 分别执行基础故障模拟

每种故障单独测试。使用新的请求或连接，避免既有连接掩盖故障。每项有明确总时限，结束后恢复到正常基线再进行下一项。

| 阶段 | 操作范围 | 需记录的结果 |
|---|---|---|
| 正常基线 | 临时环境的正常代理链 | 出口与本机基准一致；相应测试客户端确实可发起请求 |
| 静态出口不可达 | 只在临时环境使最终代理不可达 | 请求错误或超时、选择器状态、是否得到其他成功出口 |
| 前置代理不可达 | 只在临时环境使前置入口不可达 | 请求错误或超时、选择器状态、是否切换路径 |
| 代理进程暂停 | 只暂停临时环境的准确目标进程 | 请求结果；恢复后进程与代理功能正常 |
| 恢复后 | 恢复本轮临时故障 | 请求恢复；出口与基线一致；正式环境保持正常 |

可使用不含账号信息的公共检测服务，例如 `https://www.cloudflare.com/cdn-cgi/trace`。需要明确测试客户端确实使用指定代理，检查绕过列表与环境影响；真实出口只保留在私有记录。

无效测试密钥只有在确认收到服务端的 HTTP 认证拒绝时，才能作为 API 可达的证据，仍不代表登录成功或模型回复成功。CLI 只打印“密钥无效”等未溯源文本，不能排除本地校验，不能单独证明已连接 API。测试超时只说明限定时间内未取得成功结果，也可能来自重试、DNS 或客户端本身；结合基线、配置、选择器和可取得的连接证据解释。

“请求失败、选择器未切换、未取得其他成功出口”支持所测路径故障时没有成功回退的判断。若没有进程级连接或抓包证据，不能扩大写成“没有任何外联”“全机没有旁路”或“永久零泄漏”。

## 9. 真实客户端与重启验收单独安排

隔离环境通过，不能自动将以下项目填写为通过：

- 已登录的 Claude 桌面端、其辅助进程或更新器的实际断链行为。
- 小工具启动的专用浏览器中全部流量的断链行为。
- 普通浏览器、其他启动方式、IPv6、UDP 或开机最早阶段的网络行为。

机主要求继续时，再提出具体操作、账号隔离办法、恢复措施、时限和取证方法。优先使用空白测试资料，不能为了防泄漏验收，先把真实账号置于未经确认的网络路径。

真实重启需要机主保存全部应用中的工作后明确安排，不自动注销或重启。重启前准备离线恢复与观察方案；重启后核对 Claude 是否自动打开、正常启动入口是否带固定代理参数、出口是否与基准一致。

开机常驻或 `RunAtLoad` 不证明从开机第一刻就没有网络包。没有覆盖某个时间窗口或协议时，直接记录未验证。

## 10. 恢复与本机交付

恢复仅撤销本轮有备份、有记录的设置调整和临时测试资源，保留原工具、原节点、真实账号数据及其他程序。

若出现非预期失败，停止后续故障测试，使用已准备好的恢复方法。不要通过切换 `DIRECT`、更换出口、关闭全机防火墙、重装清空或修改工具来让检查变绿。

最终生成本机私有记录，并提供一份可分享的脱敏摘要。每项使用“通过、失败、未执行、无法核实”之一，写明方法、时间与证据范围。

| 项目 | 必须说明 |
|---|---|
| Claude 登录自启 | 原状态、实际调整、读回核对结果 |
| 系统窗口恢复 | 当前状态、是否为全局设置、机主授权范围 |
| 正常路径 | 哪些实际进程与入口被核对，出口是否一致 |
| 基础故障模拟 | 各场景的客户端、错误、选择器与恢复结果 |
| 真实桌面端及网页 | 实际测了哪些；未测的明确列出 |
| 真实重启 | 是否执行、观察范围及剩余边界 |
| 恢复与清理 | 正式环境状态、临时容器及凭据是否清理 |
| 本机恢复入口 | 私有备份、恢复方法及其实际可用性 |

允许的结论示例：

> 已核对 Claude 自身自启关闭；系统窗口恢复设置已核对；临时隔离环境完成指定基础故障模拟并恢复。真实桌面端逐一断链、专用浏览器全流量和真实重启尚未验收。

不得把上述示例直接当作本机已完成结果。

转发时只分享本通用任务书、原始工具安装包及脱敏摘要。不要分享任何人的应用数据、私有代理配置、备份、原始日志、截图或临时测试环境。
